01 / LAB

I work somewhere between product engineering and applied research.

Most of what appears here starts inside a real product, an engineering problem, or an experiment I needed to run.

When a piece of that work becomes useful beyond its original context, I separate it from the private system, clean the boundaries, document it, and release it here.

problem.detect()
      ↓
system.build()
      ↓
useful.part()
      ↓
clean.release()

The goal is not to publish more code.
The goal is to publish work worth keeping.

04 / RELEASE PROTOCOL

I don’t open-source something simply because I wrote it.

A repository belongs here when it does at least one of these:

[ USE ]       solves a real problem
[ REUSE ]     can survive outside its original project
[ TEACH ]     exposes a useful engineering pattern
[ MEASURE ]   produces a meaningful benchmark or experiment
[ PROVE ]     gives evidence for a technical idea

Small is fine. Half-finished noise isn’t.

Core product logic, sensitive data, private model decisions, patent-sensitive research, and work without a useful public boundary stay private.

⸻

05 / REPOSITORY SIGNALS

Every public repository should make its state obvious.

Signal	Meaning
STABLE	Useful, documented, and reasonably tested
EXPERIMENTAL	Active technical exploration
REFERENCE	Published primarily for inspection or learning
ARCHIVED	Preserved, but no longer actively developed

Licensing is intentional and repository-specific.

Some work may be permissively open-source. Other work may be available only for reference, research, or under explicitly limited terms.

If a repository does not grant a right, don’t assume one.

⸻

06 / OPERATING PRINCIPLES

READ REALITY       before designing the solution.
REDUCE             before adding.
BUILD              before theorizing forever.
MEASURE            before claiming.
DOCUMENT           what another person needs.
PROTECT            what should remain private.
RELEASE            what becomes useful beyond the project.

Progress should leave evidence.
