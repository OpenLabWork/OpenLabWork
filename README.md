// open lab

I’m Ahmet Doğan, an independent founder and developer from Türkiye.

I like taking ideas seriously enough to build them.

That has taken me through different parts of software over the years — from games and computer vision to mobile products and AI. I don’t try to fit all of that into a single title. The common part has always been the same:

find something interesting → understand the problem → build → test → keep what works.

OpenLabWork is the public side of that process.

Not everything I work on is here, and that’s intentional.

Some projects are products.
Some are private experiments.
Some are still too early to talk about.
And sometimes a small piece becomes useful enough on its own that I publish it here.

So this GitHub is not an archive of everything I have ever written.

It’s a collection of the work I think is worth leaving open.

// what gets published

There isn’t a fixed category.

A repository might be a developer tool, an experiment, a benchmark, a reusable component, a reference implementation, or simply a small solution that saved enough time to be worth cleaning up.

My filter is fairly simple:

<table>
<tr>
<td align="center"><strong>USEFUL</strong><br><sub>solves something real</sub></td>
<td align="center"><strong>REUSABLE</strong><br><sub>works outside its origin</sub></td>
<td align="center"><strong>INTERESTING</strong><br><sub>worth examining</sub></td>
<td align="center"><strong>PROVEN</strong><br><sub>has something to show</sub></td>
</tr>
</table>

If none of those are true, it probably doesn’t need a public repository.

I also don’t treat public as the default state of software.

Product internals, unfinished research, sensitive data, private infrastructure and work that needs to stay protected stay private.

No mystery. Just a boundary.

<br>

// repository language

I use a small set of signals to make the state of public work obvious.

Each repository should explain what it is, why it exists, how far it has been tested and what its license actually allows.

<br>

// a few rules I keep

Build before polishing the story.
Measure before making the claim.
Reduce before adding another layer.
Document the part another person actually needs.
Keep private work private.
Release things when they have earned a reason to exist publicly.

I don’t mind failed experiments.

A documented failure can be more useful than an impressive-looking repository that proves nothing.
